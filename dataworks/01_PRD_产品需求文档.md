# AI DataWorks — 端到端智能数据分析平台

## 一、项目背景与定位

### 1.1 为什么需要 AI DataWorks

传统数据分析链路"需求提出 → 数据开发 → SQL 编写 → 结果验证 → 报表交付"平均耗时 **3-7 天**，且存在四大核心痛点：

| 痛点 | 现状 | 根因 |
|------|------|------|
| **沟通损耗** | 业务→数仓 需求传递失真率 ~35% | 业务语言与 SQL 之间存在语义鸿沟 |
| **口径不一致** | 同一"GMV"各团队算出 5 个不同值 | 缺乏统一的指标语义层 |
| **验证成本高** | 分析师 60% 时间花在数据校对 | 缺乏端到端自动化验证机制 |
| **交付延迟** | 紧急取数平均 T+2 天 | 人力瓶颈 + 优先级冲突 |

### 1.2 核心定位

AI DataWorks 不是又一个 BI 工具或 NL2SQL Demo——它是一个 **"理解业务语义、生成可验证 SQL、产出可信分析结论"的生产级数据智能体平台**。

**一句话定义：** 用自然语言提问 → 语义层精确理解 → 生成验证过的 SQL → 给出带置信度的分析结论。

### 1.3 核心原则

1. **语义层是基石，不是可选项** —— 行业数据：直接 NL2SQL 业务准确率仅 48-54%，引入语义层后提升至 92%+
2. **大模型只做意图理解，不做 SQL 生成** —— LLM 负责 NL→结构化查询意图；语义引擎负责意图→确定性 SQL
3. **每一步都可验证** —— 从意图解析到 SQL 执行到结论生成，每个环节自动校验
4. **先正确、再智能** —— 宁可拒答给出明确理由，也不返回一个看起来对但实际错的结果

## 二、目标用户与核心场景

### 2.1 用户角色

| 角色 | 典型需求 | 频率 |
|------|---------|------|
| **业务运营** | "上周大促活动的 GMV 和同比情况如何？" | 日级 |
| **数据分析师** | "分析近 3 个月高价值用户的复购行为特征" | 日级 |
| **数据开发** | "验证新数仓模型的字段覆盖率和一致性" | 周级 |
| **管理层** | "本季度各业务线核心指标趋势 + 异常归因" | 周级 |

### 2.2 核心场景矩阵

| 场景类别 | 示例 Query | 复杂度 | 要求 |
|---------|-----------|--------|------|
| **单指标查询** | "昨天的 DAU 是多少？" | ⭐ | 100%准确、<1s |
| **多维分析** | "按渠道和城市，查看近 7 天 GMV Top10" | ⭐⭐ | 99%+、<3s |
| **同环比分析** | "本季度销售额的环比和同比变化" | ⭐⭐⭐ | 99%+、<5s |
| **归因分析** | "GMV 下跌 15%，是哪个渠道、品类或地区导致的？" | ⭐⭐⭐⭐ | 95%+、<30s |
| **预测分析** | "基于过去 12 个月趋势，预测下季度 SKU 备货量" | ⭐⭐⭐⭐⭐ | 90%+、<60s |

### 3.2 用户旅程

```
用户输入："上周北京地区 iOS 用户的 GMV 和转化率是多少？"
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 1: 意图解析（LLM）                                    │
│   指标: [GMV, 转化率]                                      │
│   维度: [地区=北京, 平台=iOS]                               │
│   时间: [上周 = 2026-06-22~2026-06-28]                     │
│   粒度: 汇总                                               │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 2: 语义映射（语义引擎）                                │
│   GMV → dws_trade_order_daily_1d.payment_amount           │
│   转化率 → dws_user_visit_conv_1d.conversion_rate          │
│   地区 → dim_region.region_name = '北京'                   │
│   平台 → dim_platform.os_type = 'iOS'                     │
│   ✅ 命名空间校验通过                                       │
│   ✅ 权限校验通过                                           │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 3: SQL 生成（确定性编译器）                             │
│   SELECT SUM(payment_amount) AS gmv,                      │
│          AVG(conversion_rate) AS cvr                      │
│   FROM dws_trade_order_daily_1d t                         │
│   JOIN dim_region r ON t.region_id = r.region_id          │
│   JOIN dim_platform p ON t.platform_id = p.platform_id    │
│   WHERE r.region_name = '北京'                             │
│     AND p.os_type = 'iOS'                                 │
│     AND t.dt BETWEEN '2026-06-22' AND '2026-06-28'        │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 4: 验证（多层校验）                                    │
│   ✅ 语法校验通过（SQL Parser）                              │
│   ✅ Explain/Dry Run 通过                                  │
│   ✅ 权限校验通过（行级+列级）                                │
│   ✅ 结果合理性校验通过（非空、量级正常、趋势一致）             │
│   置信度: 98%                                              │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 5: 执行 & 呈现                                        │
│   → 查询引擎执行 SQL                                       │
│   → 自动选择图表类型（柱状图）                               │
│   → 生成自然语言结论："上周北京 iOS 用户 GMV 为 ¥8,520 万..."│
│   → 推荐追问："要看各渠道的对比吗？"                         │
└──────────────────────────────────────────────────────────┘
```
