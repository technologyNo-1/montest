1. 这份课表和上一版的区别

上一版错误:把"融合"做成了"概括",每个阶段只留 4-5 个 bullet,把尚硅谷的具体子项和飞书的具体知识点都抽象没了,你还得自己回两份材料找细节。

学习指引

  • 学习顺序:按 1->20 顺序学,不要跳。语法基础(1-7)是地基,面向对象(9-11)是重点,高级特性(15-16)是面试加分项,网络编程(17-18)和正则(19)放最后。每天用飞书 SKILL 法:学完一个子主题,让 AI 出 5 道测试题自测,错题反复问 AI + 找 B 站视频补。
  • 重点:面向对象(类/继承/__init__/self,直接对接 Pytorch 的 nn.Module)、函数(参数类型/返回值/递归,训练代码全是函数)、列表字典(数据结构基础)、生成器迭代器(对接 DataLoader)、装饰器(@property、后续会看到 @torch.no_grad())。
  • 面试切入:
  • 问"Python 中深拷贝和浅拷贝的区别" -> 答:浅拷贝 copy.copy() 只复制最外层,嵌套的可变对象仍共享引用;深拷贝 copy.deepcopy() 递归复制所有层完全独立;举例嵌套列表 [[1,2],[3,4]] 浅拷贝改内层会影响原对象,深拷贝不会。
  • 问"is 和 == 的区别" -> is 判断两个对象是否同一内存地址(身份),== 判断值是否相等;小整数池 [-5,256] 会导致 a=256;b=256;a is b 为 True。
  • 问"装饰器原理" -> 装饰器本质是接收函数返回函数的高阶函数,@decorator 等价于 func = decorator(func);闭包是基础。
  • 问"生成器和迭代器的区别" -> 迭代器是实现了 __iter__ 和 __next__ 的对象,生成器是一种用 yield 创建迭代器的简便方式,惰性求值省内存。
  • 问"Python 垃圾回收机制" -> 以引用计数为主,辅以标记清除和分代回收解决循环引用问题。
  • 问"进程和线程的区别" -> 进程资源分配单位开销大内存独立,线程 CPU 调度单位开销小共享内存;Python 有 GIL(全局解释器锁)导致多线程不能真正并行 CPU 计算,CPU 密集型用多进程,IO 密集型用多线程/协程。
  • 项目:做尚硅谷"客户信息管理系统"(练 CRUD + 文件操作 + 面向对象)和"愤怒的小鸟"(练面向对象综合)。跑通即可,校招零基础需 2 周;社招老程序员可压缩到 1 周快速过一遍。

  • 面试切入:
  • 问"什么是反向传播" -> 前向传播算 loss 并缓存中间激活值,反向沿计算图用链式法则从输出层向输入层逐层求每个参数的偏导梯度,再用优化器更新参数;本质是链式法则的自动化。
  • 问"梯度消失和梯度爆炸的原因和解决" -> 原因:深层网络梯度连乘,激活函数导数 <1 连乘趋零(消失)、>1 连乘趋无穷(爆炸),sigmoid 导数最大 0.25 最易消失。解决:换 ReLU/LeakyReLU 激活、残差连接 ResNet、BatchNorm/LayerNorm、合理初始化 He/Xavier、梯度裁剪、LSTM 门控缓解 RNN 梯度消失。
  • 问"ReLU 相比 Sigmoid 的优点" -> ReLU 计算简单 max(0,x);正区间导数恒为 1 不饱和缓解梯度消失;产生稀疏激活;缺点:负区间导数为 0 可能导致神经元"死亡"Dead ReLU,用 LeakyReLU 缓解。
  • 问"Adam 优化器原理" -> 结合 Momentum(一阶动量 m=β1m+(1-β1)g)和 RMSProp(二阶动量 v=β2v+(1-β2)g²),用 m/√v 更新参数,做偏差校正;自适应学习率、收敛快,大模型训练首选。
  • 问"Dropout 原理,训练推理有什么不同" -> 训练时以概率 p 随机置零神经元并缩放剩余 1/(1-p) 保持期望,推理时不 dropout 用全部神经元;阻止神经元共适应防过拟合,相当于集成多个子网络。
  • 问"BatchNorm 和 LayerNorm 区别,为什么 NLP/Transformer 用 LayerNorm" -> BN 对 batch 维度归一化(每个特征跨样本算 mean/std),LN 对特征维度归一化(每个样本跨特征算 mean/std);BN 依赖 batch size 且序列长度变化时不稳定,LN 与 batch 无关适合变长序列,所以 Transformer/RNN 用 LN。
  • 问"卷积层的作用和参数量怎么算" -> 局部感受野 + 参数共享 + 平移不变性提取空间特征;参数量 = kernel_h×kernel_w×in_channels×out_channels+bias(out_channels),与图像大小无关。
  • 问"Pytorch 中 model.train() 和 model.eval() 区别" -> train 模式开启 Dropout 和 BN 用 batch 统计量;eval 模式关闭 Dropout、BN 用运行时累计的统计量。推理时务必 model.eval() + torch.no_grad()。
  • 问"autograd 原理" -> Pytorch 动态构建计算图,每个 requires_grad=True 的张量记录产生它的操作,backward() 时沿图反向用链式法则自动算所有叶节点梯度存入 .grad。
  • 项目:尚硅谷房价预测(练 MLP + 训练循环)、服装分类(练 CNN + Conv2d/MaxPool2d)。强烈建议额外照飞书 SKILL Lesson1-4 手写一遍:用 Pytorch 从零实现线性回归 -> MLP 分类 -> 体会 backward/step/zero_grad 三件套。作者说"学完 Lesson1-4 就是入门深度学习和 Pytorch,是算法必经之路"。

飞书对应细节(八股密集区,逐条对应)

飞书《LLM 模型结构》是阶段 5 的"八股弹药库",逐条对接尚硅谷子主题:

  • 飞书 2.1 Transformer 架构:2017 年论文《Attention is All You Need》提出,GPT/Claude 都基于它。基础模块 = 输入嵌入 + 自注意力机制 + 多头注意力机制 + 前馈神经网络 + 残差连接 + 层归一化--对应尚硅谷"Transformer 模型结构详解"全部子项。飞书说 Transformer"解决了并行计算和长距离依赖两方面问题,有更高效的并行计算能力和语义理解能力,是 AI 领域一次重大突破"。
  • 飞书 2.2 编码器和解码器区别:编码器处理输入序列提取上下文信息生成表示、解码器生成输出序列;编码器并行计算所有位置推理快、解码器自回归逐 token 生成无法并行推理慢--对应尚硅谷"编码器/解码器结构",也是理解 BERT(编码器快)vs GPT(解码器慢)的根。
  • 飞书 2.3 Transformer vs RNN:① RNN 逐步处理依赖前一步无法并行训练慢,Transformer 基于自注意力同时处理整个序列充分利用 GPU 训练快;② RNN 易梯度消失/爆炸、捕捉长距离依赖困难,Transformer 注意力任意两位置直接建立联系缓解长距离依赖--直接对应尚硅谷"RNN 存在问题"和"多头注意力为何增强"。飞书特别提示:虽然面试直接考 Transformer 不多,但问推理加速提到 KV-Cache 时,不懂 QKV 就弄不懂 KV-Cache;问"为什么 LLM 这几年发展这么强大"可答 Transformer 的并行计算和长距离依赖。
  • 飞书 2.4 分词器:把自然语言拆成更小单位 token、每个 token 映射成唯一 ID,为词嵌入做准备,是连接人类语言和模型语言的桥梁--对应尚硅谷"中英文分词/BPE/jieba"。
  • 飞书 2.5 Embedding:分词 + embedding 得到输入,embedding = 把离散输入(分词 id 和位置 id)分别通过词编码和位置编码转换成稠密向量最后组合成模型输入--对应尚硅谷"词表示 One-hot/Word2Vec"和 Transformer 的输入嵌入 + 位置编码。注意飞书明确"位置 id 也要 embedding",即位置编码 Positional Encoding 是 Transformer 必备(因为 Self-Attention 本身无位置信息)。
  • 飞书 2.6.1 注意力机制:对每个词生成 3 个向量 Q/K/V--Q 代表当前词要关注什么、K 代表当前词是什么、V 代表当前词能提供什么信息;用 Q,K 点积算相似度、Softmax 得注意力权重、对 V 加权得 Attention 矩阵;好处是捕捉长距离依赖、信息融合灵活、不依赖固定窗口或顺序、并行计算效率比 RNN 高--对应尚硅谷"Attention 工作原理"和"点积评分"。
  • 飞书 2.6.2 多头注意力机制:核心思想 = 通过多个注意力头并行计算不同的注意力表示,捕捉输入序列不同位置之间的关系;过程 = 生成多组 Q,K,V,每组算出 Attention 矩阵后拼接得最终结果;作用 = 让模型在不同子空间学习不同关注模式,避免单一注意力只关注一种关系--对应尚硅谷"多头注意力"。
  • 飞书 2.6.3 多头注意力为何增强:① 有利于捕捉长距离依赖;② 动态信息融合(每个词表示根据上下文动态生成而非固定);③ 并行计算;④ 可解释性强(注意力权重可可视化)--面试高频问答的现成答案。
  • 飞书 3 Bert vs GPT:BERT 和 GPT 都是基于 Transformer 的 NLP 模型,但设计理念和应用方向不同。BERT 用编码器结构、双向上下文理解、通过遮盖部分词语训练(MLM)、适合文本分类/问答等理解类任务;GPT 基于解码器结构、自回归从左到右生成文本、擅长写作辅助/对话系统等生成类任务。一句话:BERT 更擅长"理解",GPT 更擅长"生成"--这也是理解当今 LLM 为什么是 Decoder-only(GPT 路线)的关键。
  • 飞书 4 千问模型:多语言多模态大模型,Qwen3 系列 2025 年发布,参数 0.6B 到 235B,涵盖稠密模型和 MoE 架构;技术亮点 = 混合推理机制(快思考/慢思考)、MoE 架构(稀疏激活专家子网络降算力保性能)、长上下文 128K~1M tokens、多语言 119 种、约 36 万亿 tokens 预训练,后训练含指令微调 + 强化学习 RLHF + 思维链优化。
  • 飞书 5 Gemini3 模型:可控推理层级 thinking_level 参数(动态选快/慢思考)、Deep Think 模式、原生多模态(架构层面统一文本/图像/视频/音频/代码)、Agent 能力(Antigravity 平台自主规划执行验证)、100 万 tokens 上下文、MoE+TPU v6、思维签名 Thought Signatures(长链推理可验证)。
  • 飞书 6 模型和硬件:讲清"模型能不能跑"= 设备内存够不够。训练阶段显存住着:模型参数 + 梯度 + 优化器状态 + 激活值(前向缓存);推理阶段:模型参数 + KV Cache,梯度和优化器状态消失(所以推理比训练省 5-10 倍内存)。其中 KV Cache 是推理专属--自回归生成每个新 token 都要回顾之前所有 token 的 Key-Value,缓存下来避免重复计算(空间换时间),随上下文长度和并发数增长,长上下文 + 高并发时 KV Cache 可超过参数本身显存(7B 模型 16 并发 32K 上下文 KV Cache 达 64-256GB)。飞书还讲精度 fp32(4 字节)/bf16(2 字节)/fp16(2 字节)/INT8(1 字节)/INT4(0.5 字节)和混合精度训练,以及 SFT 全参(108-138GB)/LoRA(17-25GB)/PPO(244-304GB)/GRPO(122-152GB)/推理 bf16 单用户(14.25-15GB) 的显存对比。
  • 飞书 1 LLM 训练:预训练(Pre-training 非监督,海量通用未标注数据,目标语言理解/推理/世界知识)-> 微调 SFT(指令-响应数据,学会遵循指令)-> 对齐 RLHF/DPO(人类偏好数据,奖励模型或偏好分数优化,符合人类价值观安全)。Function calling = 预训练自监督 + 微调 SFT + 对齐 RLHF 三阶段共同训练出。
  • 飞书 7 模型对比选择:GPT 强在生态、Gemini 强在多模态 + 榜单、Claude 强在编码 + 长文档 + 风格客观不谄媚、DeepSeek 开源价格屠夫 + MoE 高效 + MIT 协议可本地部署、LLaMA 开源起点、Qwen3.5 多语言本地可跑。选型框架 = 场景-能力-模型三步(定义场景 Why/What/How -> 拆解能力权重 -> 匹配模型做能力适配度/成本效益 TCO/风险可控性评估)。
  • 飞书《算法 0 基础》第 3 节后训练学习:SFT(LoRA/QLoRA)、强化学习(PPO/GRPO)、训练技巧混合精度训练、数据类型 fp32/fp16/bf16、DeepSeek R1 训练技巧--这些是阶段 5 预训练模型学完后,进入大模型微调的衔接内容,飞书有专门 SKILL 讲解。

  • 面试切入(阶段 5 八股高频,结合飞书答案):
  • 问"介绍一下 Transformer" -> 2017 年《Attention is All You Need》提出,由编码器和解码器组成,基础模块是输入嵌入、自注意力、多头注意力、前馈神经网络 FFN、残差连接、层归一化;核心是注意力机制,相比 RNN 解决了并行计算和长距离依赖两个问题,是 AI 重大突破。
  • 问"自注意力机制怎么计算" -> 对每个词生成 Q/K/V 三个向量,Q 代表当前词要关注什么、K 代表当前词是什么、V 代表当前词能提供什么信息;用 Q 和 K 点积算相似度,经 Softmax 归一化得注意力权重,再对 V 加权求和得 Attention 输出;公式 softmax(QK^T/√d_k)V,除以 √d_k 缩放防止点积过大使 softmax 进入饱和区梯度小。
  • 问"Q/K/V 分别是什么" -> Q(Query 查询)是当前词发出的"我要找什么",K(Key 键)是每个词的"我是啥"用来被匹配,V(Value 值)是每个词"能提供的信息";Q 和 K 算相似度决定关注谁,加权 V 得融合表示。
  • 问"多头注意力为什么有用" -> ① 捕捉长距离依赖;② 动态信息融合;③ 并行计算;④ 可解释性强;多组 QKV 在不同子空间学不同关注模式,拼接后表达更丰富。
  • 问"为什么需要位置编码" -> Self-Attention 本身是置换不变 permutation invariant 的,打乱输入顺序结果一样,没有位置信息;位置编码给每个位置加一个唯一的位置向量;有绝对位置编码(sin/cos 正弦余弦)和相对位置编码(RoPE 旋转位置编码,LLaMA/千问用)。
  • 问"编码器和解码器区别" -> 编码器处理输入序列提取上下文生成表示,并行计算推理快;解码器生成输出序列,自回归无法并行推理慢;解码器比编码器多 Masked Self-Attention(防看未来 token)和 Cross-Attention(关注编码器输出)。
  • 问"BERT 和 GPT 的区别" -> BERT 用编码器结构、双向上下文理解、MLM 掩码语言模型预训练(随机 mask 15% 词预测)、适合文本分类/问答/NER 等理解类任务;GPT 用解码器结构、自回归从左到右生成、语言模型 LM 预测下一 token 预训练、擅长写作/对话等生成类任务;当今 LLM 主流是 GPT 的 Decoder-only 路线。
  • 问"BERT 的预训练任务" -> 两个:MLM(随机选 15% token,其中 80% 替换成 [MASK],10% 随机替换,10% 不变,让模型预测原 token,学双向表示)和 NSP(判断两句话是否原文相邻,后续 RoBERTa 发现 NSP 作用不大去掉)。
  • 问"为什么现在大模型都用 Decoder-only 不用 BERT 的 Encoder" -> Decoder-only 自回归生成统一了理解和生成、训练和推理一致、scaling law 更好、能做 in-context learning;BERT 虽双向理解强但不擅长生成,且 MLM 预训练与下游生成任务不一致。
  • 问"RNN/LSTM/GRU 有什么问题,Transformer 怎么解决" -> RNN 逐步计算依赖前一步无法并行训练慢、易梯度消失/爆炸、长距离依赖差;LSTM 用门控缓解梯度消失但参数多仍无法并行;GRU 简化 LSTM;Transformer 用自注意力让任意两位置直接建立联系根治长距离依赖、整个序列并行计算根治无法并行,但代价是计算量 O(n²)。
  • 问"什么是 KV-Cache" -> 推理时自回归生成每个新 token 都要回顾之前所有 token 的 Key 和 Value,把这些 KV 缓存下来避免每步重算,是空间换时间;长上下文 + 高并发时 KV Cache 显存可超参数本身(7B 16 并发 32K 上下文 KV Cache 64-256GB)。
  • 问"Word2Vec 的原理" -> 两种模型 CBOW(上下文预测中心词)和 Skip-Gram(中心词预测上下文);训练一个词向量矩阵,每个词查表取稠密向量;用负采样或层次 softmax 加速;缺点是一词多义无法区分、静态向量不随上下文变(Transformer 的动态 embedding 解决了)。
  • 问"jieba 分词原理" -> 基于前缀词典构建有向无环图 DAG 找所有可能切分、用动态规划找最大概率路径、对未登录词用 HMM 隐马尔可夫模型 + Viterbi 算法做新词发现;支持精确/全/搜索引擎三种模式。
  • 问"你的项目为什么选 bert-base-chinese" -> 项目是中文标题多级分类(理解类任务),BERT 编码器双向上下文理解能力强、bert-base-chinese 预训练中文语料适配中文、分类是理解类任务正是 BERT 强项、模型小(110M 参数)单卡 V100 一小时可训、Huggingface Transformers 库微调部署方便;最终多类别近 70% F1。
  • 问"你了解千问模型吗" -> 多语言多模态大模型,Qwen3 系列 0.6B-235B 含稠密和 MoE 架构;混合推理机制(快/慢思考)、MoE 稀疏激活降算力、长上下文 128K-1M、119 种语言、36 万亿 tokens 预训练,后训练含 SFT+RLHF+思维链优化;魔搭/HuggingFace 开源可商用。
  • 项目:尚硅谷"中英翻译"(练 Transformer 编码器解码器 API,手写一个 Transformer)+"AI 智评"(练预训练模型微调)+ 项目一"智能发布标题分类"(用 bert-base-chinese + Huggingface Transformers 做三级分类)。额外强烈建议照飞书《算法 0 基础》第 2 节"动手写出 Transformer"--从零用 Pytorch 实现一个 Transformer(手写 QKV/多头/FFN/位置编码/编码器解码器),做完 Transformer 八股就彻底内化。

MCP 协议(面试真题密集):MCP(Model Context Protocol,模型上下文协议)是标准化接口协议,统一 AI 模型与外部数据、工具、提示词的连接方式;客户端-服务端架构,三个关键组件 Host(运行 LLM 的应用程序)、Client(在 Host 中运行,负责与 MCP Server 通信)、Server(暴露工具、数据资源、提示模板供 LLM 使用);优点:动态能力更新(工具参数变更无需重写客户端代码)和接口标准化。与 Function Calling 的区别:标准化程度(厂商专有 vs 开放标准)、功能范围(LLM 直接调用预定义功能 vs 完整框架体系)、发现机制、可复用性。本地 Server 与远端 Server 对比:本地用 Stdio 协议安全性低延迟低扩展受限生态好,远端用 HTTP 安全性高延迟高扩展强。传输协议:远端 2025 年 3 月重大更新,从有状态 HTTP 长连接 + 强制 SSE(Server-Sent Events)改为无状态协议,主要通过标准 GET 和 POST HTTP 请求完成交互,SSE 变为可选增强功能,更接近 REST 风格;本地通过 STDIO 通信。MCP Server Tool 设计六原则:(1)入参参数最少化、类型严格、约束内联(inputSchema 是给 LLM 看的说明书,必填参数少、给默认值、用枚举收敛、约束写进 schema);(2)出参结构化返回 LLM 友好(outputSchema 声明返回结构,向后兼容附带纯文本版本,统一格式化成带标题/来源引用/置信分数的可读文本而非裸 JSON);(3)错误处理双层(协议级用标准 JSON-RPC error code;业务级通过 isError:true+error message,错误信息要告诉 LLM 下一步该怎么办而非丢堆栈);(4)Tool Annotations 声明副作用(只读/破坏性/幂等/与外部世界交互四个属性,Client 据此决定是否弹确认框);(5)粒度控制单一职责工具间可组合(拆分粒度适中,上游输出可直接作为下游输入);(6)安全与校验输入校验输出脱敏(校验所有输入、访问控制、限流、路径穿越检查、注入防护、敏感信息脱敏,始终人类在回路中)。

Agent 记忆功能(必考):分短期记忆和长期记忆。短期记忆存在于上下文窗口,包含最近对话消息、智能体回复、工具调用结果、当前交互反思,容量有限需通过总结旧对话片段、强调关键细节维护;LangChain 用 ConversationBufferMemory,LangGraph 通过图状态 State 和检查点 Checkpoint 实现短期记忆,以 thread_id 区分。长期记忆存储需跨会话保留的信息,数据存在运行环境之外(数据库、知识图谱、向量数据库);LangChain 用 VectorStoreRetrieverMemory 将信息变嵌入向量存 Chroma/weaviate/FAISS;LangGraph 通过存储库 Store 接口(类似键值数据库,支持向量嵌入语义检索)实现。OpenClaw 的 Compaction 机制:上下文 token 接近模型窗口上限时,把最近约 20,000 tokens 消息原样保留,更早旧消息用 LLM 分块生成结构化摘要替代,摘要强制保留任务状态、决策理由、TODO 和关键标识符。短期->长期自动沉淀:OpenClaw 压缩前会静默触发一轮 agent 回合,提醒模型把当前对话重要信息写入记忆文件。

OpenClaw:四层记忆架构(类似计算机存储层次):(1)Bootstrap Files(≈硬盘)--Agent 永久身份与规则,完全免疫 Compaction,工作空间 Markdown 文件每次会话从磁盘读取注入上下文,文件清单 SOUL.md(人格语气边界)、AGENTS.md(操作指令行为规则)、USER.md(用户身份)、TOOLS.md(工具使用说明)、IDENTITY.md(Agent 名称与风格)、MEMORY.md(策展长期记忆,仅主会话加载)、HEARTBEAT.md(心跳任务清单可选)、BOOTSTRAP.md(首次运行仪式一次性),位置 ~/.openclaw/workspace/,单文件 20,000 字符总计 150,000 字符超出截断;(2)Session Transcript(≈文件系统日志)--完整对话历史以 JSONL 文件追加写入磁盘,跨重启持久;(3)Context Window(≈RAM 内存)--模型当前能看到的所有内容,满了触发压缩;(4)Retrieval Index(≈搜索引擎)--SQLite 语义搜索记忆文件,对 MEMORY.md 和 memory/YYYY-MM-DD.md 建混合搜索索引(向量语义搜索 + BM25 关键词搜索按 7:3 权重混合)。Compaction 触发:自动(溢出恢复--模型返回 context overflow 错误->压缩->重试;阈值维护--成功完成一轮后 contextTokens > contextWindow − reserveTokens 时触发)和手动(/compact)。总体架构三层:触发层(消息渠道 Discord/Telegram/Slack/WhatsApp)-> 网关层 Gateway(路由/session 管理/并发控制)-> Agent 层。5 种触发源:Message、Heartbeat(心跳周期性唤醒自检续跑)、Cron(定时任务)、Webhook、Hooks。Gateway 核心职责:连接管理、协议转换、路由分发、安全控制;关键边界:Gateway 只做路由不调 LLM 不执行工具。Agent 框架本质是递归 Centralized 架构:Parent Agent 作为中心用 LLM 决策任务拆解向下 spawn 子 Agent,子 Agent 可继续 spawn 孙 Agent 形成递归 Orchestrator-Worker 树;多 Agent 编排完全基于 LLM 标准 Tool Use 机制--sessions_spawn 被注册为普通工具,系统提示词注入触发规则"If a task is more complex or takes longer, spawn a sub-agent"。选 Centralized 的理由:对话"一进一出"结构天然要求有且只有一个 Agent 对最终回复负责。

Multi-Agent 架构(Google 论文《Towards a Science of Scaling Agent Systems》25 年 12 月):5 种典型架构:(1)SAS 单体--一个 Agent 顺序感知->推理/规划->行动->迭代,LLM 调用 O(T)、通信开销 0、并行化 1,最简单最稳,单体基线不错(经验阈值约 45%)再加协调收益递减或为负;(2)MAS Independent 独立多体--多 Agent 独立并行做同一任务最后聚合/投票,O(N·T)、通信 1、并行化 N,并行度最高但缺少互相纠错,错误放大最严重 17.2×;(3)MAS Centralized 中心化--一个协调者 Orchestrator 分解任务、分派子任务、收集结果、裁决收敛,O(R·N)、通信 R·N,稳健性更好错误放大从 17.2× 控到 4.4×,可并行金融推理任务提升可达 +80.9%;(4)MAS Decentralized 去中心化辩论--Agent 点对点交流/辩论多轮质询改进最终多数表决,O(D·N)、通信 D·N²,多视角对齐与相互检验;(5)MAS Hybrid 混合式--集中式层级管控之上允许定向点对点交流,O(R·N+P·M)。设计原则:多 Agent 不一定比单 Agent 好,强顺序长推理链、单体 Agent 能力已较强(基线≥45%)、工具密集且预算固定三种情况用单 Agent 更好。

I. A2A 协议:A2A(Agent-to-Agent)核心目标是让不同智能体之间能够互操作和协作,即使它们来自不同厂商、框架或运行环境。4 个关键特点:(1)互操作性--通过标准化消息格式和通信机制让不同 Agent 发现彼此并交换任务或信息,常用技术 JSON-RPC、HTTP、SSE;(2)Agent 卡片(描述元数据)--每个 Agent 通过"卡片"描述自己的能力、接口、身份和安全策略;(3)长时协作与异步交互--支持多轮对话、任务委派、进度更新、流式响应;(4)内部实现不透明--调用方只知道对方是 Agent,不关心它内部用什么模型或工具。

K. Loop Engineering & Graph 工程(2026 年 6 月火):起源:"龙虾之父"Peter Steinberger(OpenClaw 作者)在 X 发帖"别再给 coding agent 写提示词了,你应该去设计循环来驱动这些 agent";Anthropic Claude Code 负责人 Boris Cherny 在播客背书"以前我跑五到十个 Claude,我的工作是写提示词让它写代码,现在又往上抽象了一层,我跑的是一堆 loop,是这些 loop 在 prompt Claude";OpenAI Codex 负责人 Tibo 转发,LangChain Lance Martin 写长篇解读。行业演进脉络:提示词工程 -> 上下文工程 -> Harness 工程 -> 循环工程(Loop Engineering),人和 AI 打交道的基本单位正从"一次对话"变成"一个完整回路"。Loop 工程本质是把反复发生的"行动、观察、修正、再行动"写成规则交给系统自动跑;与 cron 定时任务的区别--决策者在循环里面,cron 跑固定脚本第一步第二步永远一样,loop 跑一个 agent 看当前状态自己选下一步干啥,会重试会回滚会搞不定时停下,即"cron 是执行脚本,loop 是模仿一个工程师"。一个 loop 至少回答五个问题(目标、触发、执行、终止、反馈)。Graph 工程是 Loop 的进一步图化编排。

RAG 优化技术(RAG.md):RAGAS 评估四大指标:faithfulness(忠实度,答案是否基于检索上下文)、answer relevance(答案相关性)、context precision(上下文精确率)、context recall(上下文召回率);注意无行业标准--MLflow 用 1-5 分、Ragas 用 0/1、LlamaIndex 让模型答 YES/NO,换工具换提示词分数不可比。向量数据库 4 款:Milvus(基于 Faiss/Annoy,支持数十亿甚至万亿级向量,毫秒级检索,数据分片/持久化/流式摄取/混合搜索,可部署 K8s)、Weaviate(鲁棒云原生可扩展,百万级毫秒,缺点只支持 HNSW 一种检索算法)、Chroma(AI 原生开源轻量,针对 RAG 场景,单机方案,FAISS 索引不支持 GPU,万-十万级,适合本地原型)、Qdrant。意图识别三步:判断问题类型(7 种--定义类、事实类、流程类、比较类、总结类、政策类、排查类)-> 抽取实体与槽位 -> 决策检索策略(直接检索、查询改写、查询扩展、HyDE、多目标分解、向用户询问 6 种)。Chunking 策略:固定长度切分只保证长度不保证语义完整;正确做法"语义优先 + 长度约束 + overlap + 评估验证",先看文档类型--FAQ 强结构化数据一条一个 Document 不强切,技术文档/用户协议/SOP 长文本用递归切分按标题段落句子最后长度兜底;RecursiveSplitter 按分隔符优先级递归切(先 \n\n 段落 -> \n 换行 -> . 句号 -> 空格);chunk overlap 重叠窗口防上下文断裂;ParentDocumentRetriever 用 Parent_splitter(父文本块输入 LLM 大小)和 child_splitter(子文本块召回大小)存父子映射。检索:Dense 稠密向量语义匹配(把 query 和 chunk 嵌入同一向量空间算余弦相似度,强项语义理解但精确关键词不敏感)+ Sparse 稀疏 BM25 词频匹配(对精确关键词专有名词敏感但不理解语义),混合检索两路并行 + RRF 融合(只看排名不看分数不需归一化)。检索优化:HyDE(Hypothetical Document Embeddings 假设性文档嵌入--为短抽象问题用 LLM 生成假设答案再拿假设答案做检索,因假设答案和文档用词更接近)、ParentDocumentRetriever、MultiQueryRetriever(用 LLM 改写扩充生成多个检索表达)、重排序精排、metadata 元数据过滤。精排 4 种:Cross-Encoder 交叉编码器(query 和每个候选文档拼一起输入模型判断相关性,语义匹配强分数稳定但每候选单独过模型延迟算力高)、LLM 精排、规则精排、混合精排。Embedding 模型三类:句向量模型 SBERT/Sentence Transformers、检索专用开源模型 E5/BGE/GTE、商业 Embedding API OpenAI/Cohere/Voyage。GraphRAG 两种:基于语料库的 GraphRAG(切分文本块 -> 抽取实体与关系 -> 构建知识图谱 -> 构建图社区社区发现 -> 生成社区摘要 -> 全局查询 Global Search/局部查询 Local Search,适合实体关系密集跨文档关联全局归纳)、基于已有知识图谱的 GraphRAG。KG-RAG:普通语义检索拿到 chunk 后映射到知识图谱实体,沿图边扩展检索补齐关系链。Agentic RAG(Self-RAG/Corrective RAG):把 RAG 从固定流水线变成有决策能力的 Agent,让模型自己判断检索结果够不够、不够再检索或换策略、自我纠错。RAG 趋势:Boris Cherny(Claude Code 核心作者)第一手复盘--早期 Claude Code 真的用过 RAG(用 Voyage embedding 给代码库建索引),后来整个放弃转向 agentic search(glob+grep 常规代码搜索),原因:代码库频繁变 RAG 索引难维护/语义检索不如精确文本搜索/agent 自主搜索更灵活。

面试要点(飞书 Agent 场景题与高频八股,含答案要点)

  1. 什么是 Agent?构成要素? Agent 是能感知环境、自主规划、调用工具、迭代行动直到完成目标的系统。构成要素:大模型(推理决策核心)、规划(任务拆解与多步推理)、工具(Function Calling/MCP 扩展能力边界)、记忆(短期上下文 + 长期知识库)、循环(ReAct 感知->推理->行动->观察)。
  2. Function Calling 怎么训练出来的? 三阶段:预训练自监督 -> 微调 SFT(理解何时调用、调用格式)-> 对齐 RLHF(优化调用结果符合人类习惯)。
  3. MCP 和 Function Calling 的区别?传输协议? 区别:标准化程度(厂商专有 vs 开放标准)、功能范围、发现机制、可复用性。MCP 三组件 Host/Client/Server。传输协议:远端 2025 年 3 月从有状态 HTTP+SSE 改为无状态标准 GET/POST,SSE 变可选;本地用 STDIO。
  4. MCP Server Tool 设计原则? 六位一体:入参参数最少化类型严格约束内联、出参结构化返回 LLM 友好(outputSchema+纯文本兜底)、错误处理双层(协议级 JSON-RPC error code + 业务级 isError:true 告诉 LLM 下一步)、Tool Annotations 声明副作用(只读/破坏性/幂等/外部交互)、粒度单一职责可组合、安全校验输入校验输出脱敏。
  5. Agent 记忆如何实现?短期窗口满了怎么办? 短期在上下文窗口(LangChain ConversationBufferMemory,LangGraph State+Checkpoint 按 thread_id 区分);长期存外部(LangChain VectorStoreRetrieverMemory,LangGraph Store 命名空间 + 语义检索)。窗口满了用 Compaction:OpenClaw 保留最近 ~20,000 tokens 原文,更早旧消息用 LLM 分块生成结构化摘要,强制保留任务状态/决策理由/TODO/关键标识符,压缩前静默触发一轮把重要内容写入长期记忆。
  6. 多 Agent 和单 Agent 的区别?常见多 Agent 架构?怎么选? 五种架构:SAS(O(T) 最简单基线≥45% 再加协调收益递减)、Independent(O(N·T) 并行最高错误放大 17.2×)、Centralized(O(R·N) 错误放大控到 4.4× 有权威收敛)、Decentralized(O(D·N) 辩论多视角通信 D·N²)、Hybrid(O(R·N+P·M))。选型:强顺序长推理链、单体能力强≥45%、工具密集预算固定时用单 Agent。
  7. 什么是 ReAct 范式? Reasoning+Acting,思考->行动->观察结果->再思考的多轮迭代。决策权在 LLM 手里,Think 和 Act 交替而非一次性,工具结果回灌下一轮上下文。
  8. OpenClaw 的四层记忆?为什么选 Centralized? 四层:Bootstrap Files(≈硬盘 永久身份规则免疫 Compaction)、Session Transcript(≈文件系统日志 JSONL 完整对话历史)、Context Window(≈RAM 模型当前能看到的内容)、Retrieval Index(≈搜索引擎 SQLite 语义搜索)。选 Centralized 因对话"一进一出"结构天然要求有且只有一个 Agent 对最终回复负责。
  9. Hermes 和 OpenClaw 的区别?为什么 Hermes 能自我进化? 区别在 Agent 层多一圈自进化闭环(Think-Act-Remember-Reflect 第四步 Reflect)。自我进化核心"like back propagation but for prompts instead of model weights"--像反向传播但更新的不是模型权重而是 prompt/记忆/skill,每约 10-15 次 tool call 触发反思,三路沉淀:memory 事实性知识、Skill Library 程序性流程、Honcho 用户偏好。记忆从四层扩展到五层。
  10. 什么是 Loop Engineering?和 cron 区别? 2026 年 6 月火,把反复发生的"行动观察修正再行动"写成规则交给系统自动跑。演进:提示词工程 -> 上下文工程 -> Harness 工程 -> 循环工程。和 cron 区别:决策者在循环里--cron 跑固定脚本永远一样,loop 跑 agent 看当前状态自己选下一步会重试会回滚会停下,"cron 执行脚本,loop 模仿工程师"。
  11. 什么是大模型幻觉?如何产生?如何解决? 幻觉是模型自信输出不符合事实的内容,本质是概率预测器不是知识库。因果链四层:根因(概率预测器错误随长度累积)-> 燃料(训练数据截止/稀缺/污染/过拟合)-> 扳机(预训练顺着说 + 后训练偏好尽量给答案)-> 电路(H-Neurons 清华论文,极少数神经元驱动过度顺从,与流畅性纠缠无法删除)。解决 7 类:外部工具、RAG(最主流)、RLHF/DPO 奖励承认低置信度、CoT/Self-Ask、融合模型投票、事实核查、H-Neurons 幻觉探测器(监测抑制预警不删除)。
  12. Agent 系统应该测试评估哪些东西? 按 EDD 先定义"怎么才算成功"再开发。上线前:选型期(榜单粗筛 + 硬约束 + 私有数据集终筛)、组件评测(Prompt 鲁棒性/RAG 召回忠实度/工具调用调错率填参率/规划推理)、系统评测(端到端成功率/轨迹评测 Trajectory/多轮用户模拟/多 Agent 协作)、发布闸门(质量分/Pass@k/Pass^k/P95 延迟/token 成本/最大步数/安全红队/误拒率)。上线后:A/B 灰度 + logs/traces/metrics + 漂移异常检测。
  13. 什么是 LLM-as-a-judge?有哪些偏见? 用一个通常更强的模型按 rubric 给另一个 Agent 输出打分,三种用法(单点打分/对参考打分/两两比较),GPT-4 裁判与人类一致性 85% 高于人类间 81%。三大偏见:自我偏好、首位偏差、冗长偏差。金句"看不到裁判模型和提示词就不要相信它给的分数"。
  14. RAG 系统怎么评估?RAGAS 指标? RAGAS 四指标:faithfulness、answer relevance、context precision、context recall;无行业标准。检索用 Hit Rate@K、MRR;消融实验跑 Dense Only/BM25 Only/BM25+Dense+RRF/Hybrid+Cross-Encoder Rerank 四组;记录 P50/P95 延迟、Rerank 耗时、Token 成本。
  15. HyDE 是什么?为什么有效? HyDE(Hypothetical Document Embeddings 假设性文档嵌入):为短抽象问题用 LLM 先生成一个假设答案,再拿假设答案做向量检索。有效因假设答案和文档用词/语义更接近,比直接拿短问题检索召回更准。需保留原始 Query 作一路召回防语义漂移。
  16. 为什么要做混合检索(Dense+BM25)? Dense 稠密向量语义匹配强但精确关键词不敏感;Sparse BM25 词频匹配对精确关键词专有名词敏感但不理解语义(中文问"灌进系统"文档写"ingestion pipeline"匹配不上)。两路互补,RRF 融合只看排名不看分数不需归一化,还有 Graceful Degradation 任一路出错自动降级另一路。
  17. GraphRAG 解决什么问题?基于语料库的 GraphRAG 流程? 解决传统向量检索难处理跨文档关联推理。流程七步:切分文本块 -> 抽取实体与关系 -> 构建知识图谱 -> 构建图社区(社区发现)-> 生成社区摘要 -> 全局查询/局部查询。适合组织关系/供应链/科研文献/法律案件/设备故障链路。
  18. 信用卡欺诈检测 Agent 怎么设计?(滴滴真题) 四层框架:触发层(事件驱动 + 分级路由,白名单/低风险秒级放行,黑名单秒级拦截,灰区可疑才进 Agent 层,Gateway 只做管道不调 LLM 做幂等去重)-> Agent 架构(预定义骨架 + 有界 ReAct 混合式,Worker 池四维度地理速度/行为偏移/商户风险/设备关联网络可并行,Orchestrator 的 Think-Act-Observe 决定调不调调哪几个)-> Critic 模式两级复核(Worker 内部自检打置信度,独立复核 Critic 在融合后决策前用独立干净上下文做对抗式复核压低误报)-> 业务逻辑(决策分档把风险分翻译成可执行动作:放行/OTP 告知/拒绝/转人工)。选 ReAct 而非 Workflow 的判据:流程是否确定--固定管线用 Workflow,需 Agent 动态判断证据是否足够定案用 ReAct。
  19. PDF 乱码多 MarkItDown 转换效果不好怎么办? 三层防线(Garbage In Garbage Out):第一层入口文档质量检测前处理(提取前几页算有效字符占比,低于 80% 阈值直接拒绝入库);第二层业务场景影响有限(企业内部知识库文档多为 Word/LaTeX 导出文本型 PDF,MarkItDown 底层 pdfminer.six 对标准文本型 PDF 准确率高);第三层 Transform 阶段 LLM 兜底(ChunkRefiner 合并被切断段落、剔除页眉页脚残余乱码、补全上下文)。
  20. BM25 怎么构建?稀疏向量还是倒排索引? 倒排索引不是稀疏向量(因 ChromaDB 只支持稠密向量故自建倒排索引)。两步:建索引(SparseEncoder 用 jieba 分词统计词频,BM25Indexer 汇总建成词->posting list 倒排结构,每条 posting 存 chunk_id/词频 tf/文档长度,预算 IDF 和全局平均文档长度)-> 查询在线打分(query 分词查 posting list 用 BM25 公式打分求和排序返回 top-k)。
  21. 为什么用 LangChain 不用 Semantic Kernel? LangChain 生态丰富灵活适合快速原型、社区文档最佳实践多、混合检索 + Ragas 评测集成方便;Semantic Kernel 是微软内部框架用得不多。注意 LangChain 四缺点:依赖过多复杂度高、频繁更新接口不稳定、链式调用性能延迟、高度抽象定制困难,故项目用可插拔工厂模式 + 配置驱动规避。
  22. 你的 Agent 项目任务完成得怎么样?有没有学习/反思能力? 有,设计 AutoDream 记忆巩固任务:累计 5 次会话且间隔 24 小时后按检查点增量回放咨询/预约/反馈事件,经结构化抽取、向量去重、冲突降权、置信度更新写回 UserPreference,供推荐和回访读取;任务锁 + 处理水位 + 变更日志保幂等重试。这是参考 Claude Code 未公开 AutoDream、Hermes 自进化循环、OpenClaw Pre-Compaction Memory Flush 的设计。

1. 大模型框架原理 - GPT 系列模型演进历史:GPT-1(Decoder-Only 首次验证无监督预训练 + 有监督微调)-> GPT-2(Zero-shot,扩大到 15 亿参数,去掉微调直接预测下一 token)-> GPT-3(1750 亿参数,In-context Learning/Few-shot)-> InstructGPT(引入 RLHF,SFT+RM+PPO 三阶段)-> GPT-3.5/ChatGPT(对话对齐)-> GPT-4(多模态、MoE)-> GPT-4o(原生多模态实时)。核心脉络:参数规模扩大 + 数据扩大 + 对齐技术(RLHF/RLAIF)。 - 当今主流 LLM 体系概览:闭源(GPT/Claude/Gemini)与开源(Llama/Qwen/DeepSeek/Mistral/GLM)。 - LLM 基础架构:输入层、Transformer Block、输出层:输入层(Tokenization BPE/SentencePiece/Tiktoken -> Token Embedding 查表 vocab_size×hidden_dim -> 叠加 Position Embedding);Transformer Block(多头自注意力 + FFN 两层 MLP 中间用 SwiGLU/GELU + 残差连接 + LayerNorm/RMSNorm,Decoder-Only 用因果掩码 Causal Mask);输出层(LM Head hidden_dim->vocab_size 线性变换 + Softmax)。 - LLM 架构演进:Attention(标准 MHA -> MQA 所有 query 头共享一组 KV -> GQA 分组共享 KV Llama2/3 采用 -> MLA Multi-head Latent Attention DeepSeek 采用 KV 压缩到低维潜在向量减少 KV Cache);FFN(标准 FFN -> GeGLU/SwiGLU 门控线性单元 Llama 采用 SwiGLU);残差与归一化(Post-LN -> Pre-LN 更稳定 -> Sandwich-LN;RMSNorm Llama 系列采用去掉均值中心化和偏置只做缩放计算更快);位置编码(绝对位置编码 Sinusoidal 正余弦 -> 可学习位置编码 -> 相对位置编码 RoPE 旋转位置编码 Llama/Qwen 采用支持长度外推 -> ALiBi 线性偏置注意力)。 - 主流开源 LLM 架构:DeepSeek V3(MoE 架构 Mixture of Experts 总参数 671B 激活参数 37B,采用 MLA + DeepSeekMoE 细粒度专家 + 共享专家 + Multi-Token Prediction MTP 多 token 预测 + FP8 训练);Llama 4(原生 MoE 架构,多模态早期融合文本与视觉 token,GQA,RoPE,超长上下文);Qwen3(Dense 与 MoE 双版本,采用 GQA + SwiGLU + RoPE + QK-Norm,支持 thinking mode/non-thinking mode 切换);GPT-OSS(OpenAI 开源模型,MoE 架构);MoE 架构共性(路由 Router 决定 token 分配给哪些专家,稀疏激活降低计算量)。

2. 大模型微调核心 - 微调原理:BaseModel / InstructModel / ChatTemplate:BaseModel(预训练后基座,只会续写,如 Qwen2.5-7B、Llama3-8B);InstructModel(经过指令微调 + 对齐,能遵循指令多轮对话,如 Qwen2.5-7B-Instruct);ChatTemplate(不同模型的对话模板 System/User/Assistant 角色标记与特殊 token,如 <|im_start|>/<|im_end|>,微调与推理必须使用同一套模板否则效果崩溃。飞书项目特别强调"采用原生 Chat Template")。 - 微调数据集格式:alpaca 指令跟随格式({"instruction": "...", "input": "...", "output": "..."} 单轮);shareGPT 多轮对话格式({"conversations": [{"from": "human", "value": "..."}, {"from": "gpt", "value": "..."}]} 多轮。飞书后训练项目用 ShareGPT 格式做 SFT/DPO)。 - 微调算法:全参微调(Full Fine-Tuning 训练所有参数,适应性强但成本高显存大易过拟合);参数高效微调 PEFT--LoRA(Low-Rank Adaptation 低秩分解,冻结原权重 W,新增 ΔW=A×B,A: d×r,B: r×d,r 为秩,只训练 A、B)、QLoRA(Quantized LoRA 把 base model 量化到 4-bit NF4,LoRA 适配器保持 fp16/bf16 再微调。飞书原文:"QLoRA 通过 4-bit 量化,使 650 亿参数的大模型可以在单张 48GB GPU 上微调")、Adapter Tuning(插入新模块)、Prompt Tuning/P-Tuning(在输入前加可训练前缀不改变模型结构);分布式训练--数据并行 DP(每张卡完整副本切分数据梯度同步)、张量并行 TP(把单层权重矩阵按列/行切分到多卡 Megatron-LM 风格)、流水线并行 PP(把不同层分到不同卡 micro-batch 流水)、专家并行 EP(MoE 场景把不同专家放到不同卡)、ZeRO(Zero Redundancy Optimizer 零冗余优化器 DeepSpeed 提出,分三阶段 ZeRO-1 切优化器状态/ZeRO-2 +切梯度/ZeRO-3 +切模型参数,消除数据并行中的冗余)。 - 微调工具链:Huggingface SFT(trl.SFTTrainer 标准 SFT 训练器);Huggingface Accelerate(统一封装多卡/混合精度/分布式启动);Unsloth(对单卡 LoRA 训练做算子级加速,训练速度提升 2 倍,显存降低);DeepSpeed(微软分布式训练框架,ZeRO、混合精度、offload 到 CPU);LLaMA-Factory(低代码微调框架,YAML/命令行配置即可跑 SFT/DPO/QLoRA,飞书后训练项目即用 LLaMA-Factory 搭建 LoRA/QLoRA SFT)。 - 模型部署与推理:vLLM(高并发推理引擎,核心是 PagedAttention + Continuous Batching);PagedAttention(把 KV Cache 按页 block 管理类似 OS 虚拟内存分页,避免显存碎片化,显存复用率高);Continuous Batching(异步调度器把不同请求动态合并,请求完成即释放槽位新请求随时加入);KV Cache 高效复用(缓存注意力计算的 Key/Value 避免每生成一个 token 就重算前面所有 token 的 KV);OpenAI API 兼容服务化部署(用 vLLM/llama.cpp server 暴露 /v1/chat/completions 接口)。 - 模型评估:EvalScope(魔搭 ModelScope 开源评测框架,支持 MMLU、CMMLU、GSM8K、HumanEval 等基准);评测基准(知识类 MMLU/CMMLU/C-Eval、数学推理 GSM8K/MATH、代码 HumanEval/MBPP、对话 MT-Bench/AlpacaEval);推理性能压力测试(吞吐 tokens/s、TTFT 首 token 延迟、P95/P99 延迟、并发数);交互式测试报告。 - 文摘引擎(子项目,Qwen3-4B + LoRA):基于 Qwen3-4B + LoRA 微调,单卡快速迭代,核心数据抽取准确率从 90% 提升至 96%;全岗位报表场景(运营/供应链/客服),日报周报生成时间压缩 70%-90%;2048 token 上下文窗口;异常数据智能归因 + 规则校验;加密传输与脱敏;闭环迭代。

3. 强化学习核心 - 基础理论:MDP(马尔可夫决策过程五元组 S/A/P/R/γ,马尔可夫性下一个状态只依赖当前状态与动作);贝尔曼方程(V(s)=Σ_a π(a|s) Σ_{s'} P(s'|s,a)[R(s,a,s')+γV(s')] 状态价值函数递推关系);蒙特卡罗方法 MC(通过完整 episode 采样估计价值,无偏但方差大需等回合结束);时序差分 TD(V(s) ← V(s)+α[R+γV(s')-V(s)] 自举更新,无需等回合结束方差小但有偏);策略梯度法(直接对策略 π_θ 求梯度,J(θ)=E[Σ γ^t R_t],∇J(θ)=E[∇log π_θ(a|s)·G_t]);REINFORCE(最简单的策略梯度算法用蒙特卡罗回报 G_t 作权重方差大);Actor-Critic(Actor 网络输出策略 π_θ,Critic 网络输出价值函数 V_φ,Critic 估计基线降低方差)。 - 高级理论:PPO(Proximal Policy Optimization 近端策略优化,限制策略更新幅度,用 PPO-Clip min(r_t·A_t, clip(r_t, 1-ε, 1+ε)·A_t) 防止更新过大导致崩溃。飞书智能评论项目集成 PPO-Clip + KL 散度惩罚);DPO(Direct Preference Optimization 直接偏好优化,直接用偏好数据 chosen/rejected 对优化策略,绕过奖励模型和 PPO,损失函数基于 Bradley-Terry 模型推导。代表 LLaMA-2-Chat、Mistral-Instruct。飞书后训练项目在 SFT 权重上做 DPO);GRPO(Group Relative Policy Optimization 组相对策略优化,DeepSeek 提出,对同一 prompt 采样一组 group 回答,用组内相对优势组内奖励减均值除标准差替代 Critic 价值网络,省去价值模型降低显存。DeepSeek-R1 用 GRPO 做强化学习)。 - 基于强化学习微调大语言模型:RLHF(Reinforcement Learning with Human Feedback 人类排序数据训练奖励模型 -> PPO + KL Penalty 优化。代表 ChatGPT、Claude);使用 PPO 微调 LLM(Actor=SFT 模型,Critic=价值头,Reward Model 打分,KL 惩罚防止偏离 SFT 参考模型);使用 DPO 微调 LLM(构造 chosen/rejected 偏好对直接优化策略);使用 GRPO 微调 LLM(组内采样 + 相对优势,无需价值网络)。 - 案例:从零实现 DPO 之"如何训练一个智能客服";从零复刻 DeepSeek-R1 之"如何训练一个带思维链的医疗助手"。

来自《模型微调.md》 - SFT 方案有哪些:大方向分全量微调(传统方法训所有参数适应性强适合复杂任务但成本高易过拟合)和部分参数微调。部分参数微调又分两类:① 在模型结构中插入新模块(Adapter Tuning、LoRA、QLoRA,不改变原始参数只训练新模块,适用于中大型任务);② 在输入前添加可训练提示/前缀引导模型(Prompt Tuning、P-Tuning,不改变模型结构,参数极少,适用于轻量任务或快速迭代)。 - LoRA 原理(拼图比喻):整个模型参数是一幅完整拼图,LoRA 只调整几个特定拼图模块,不重拼整个模块。具体通过低秩分解把大矩阵 W 拆成两个小矩阵 A、B,只微调 A、B 中的参数,不改变大权重矩阵 W,保持原模型稳定性同时用少量参数适应新任务。 - LoRA 常见参数:r(秩) 控制低秩矩阵大小,常用 4~64,典型 r=16 或 8,简单任务用 8 复杂任务用 16~32;alpha(缩放因子) 通常为 r 的 1~2 倍,常用 16~128;target_modules 通常选注意力层;learning_rate 1e-4~5e-5,LoRA 只训小参数可稍高,飞书项目用 2e-4;batch_size 影响显存和训练稳定性;epochs 3~5 轮防过拟合。 - "你是怎么做微调的"四步法(飞书作者面试答法):(1)确定目标/做好选型(先判断能否用提示词工程或 RAG 解决成本更低;考虑硬件,16GB 显存可用 LoRA,13B 模型可能用 QLoRA;飞书项目核心目标是压缩模型同时保留精度,用远端 Azure AI Foundry,训 Qwen2.5-7B-Instruct,用 LoRA);(2)数据集准备(真实用户邮件标注 + GPT-4 合成数据 + Enron Email Dataset 公开数据,共 500 条,文本标准化、敏感信息去除);(3)确定参数、微调、部署(r=8、alpha=16、学习率 2e-4;监测训练/验证集损失曲线,验证集升训练集降则过拟合,用早停 + 正则化;训练后用 PEFT 库合并适配器权重和基础模型);(4)验证和评估(分类用 F1-Score,文本生成用 BLEU/ROUGE,通用对话用 MT-Bench;飞书项目是结构化信息提取任务,用字段级 F1 + 精确匹配,对 title/时间/地点分别算准确率)。 - 强化学习方案有哪些:① 基于人类偏好的 RL -> RLHF:奖励来源是人类排序数据->奖励模型;优化方式 PPO + KL Penalty;目标是对齐人类偏好安全和价值观;代表 ChatGPT、Claude。② 基于 AI 偏好的 RL -> RLAIF:奖励来源是强大教师模型(如 GPT-4)生成偏好排序;优化方式同 RLHF(PPO);目标是降低人工标注成本;代表 Anthropic 的 Constitutional AI。③ 基于偏好数据的直接优化 -> DPO:奖励来源是偏好数据(人类或 AI);优化方式直接优化策略不训练奖励模型;目标是简化 RLHF 避免 PPO 复杂性;代表 LLaMA-2-Chat、Mistral-Instruct。 - SFT vs RLHF 区别:目标(SFT 让模型有基本语言能力和执行任务能力;RLHF 让回答更符合人类偏好安全价值观);方法(SFT 有监督数据是问题-答案;RLHF 强化学习数据含多个答案 + 排序 + 奖惩模型);步骤(RLHF 通常在 SFT 基础上进一步优化)。 - 数据集准备:来源(内部数据、公开数据 Hugging Face Datasets/Enron Email Dataset、人工标注、数据合成大模型生成);清洗前处理(文本标准化统一大小写去特殊字符和 html tags、敏感信息去除名字电话合规性、平衡数据分类任务避免某类过多、标签纠正避免矛盾如 angry 与 frustrated 选一或合并、统一格式分类 {Text->Label} 问答 {Context, Question->Answer});判断数据是否值得训练的六标准(腾讯 AIAgent 暑期实习一面真题):是否真实覆盖业务问题(高频高价值易错场景)、是否有明确可学习模式(输出风格/任务格式/领域表达/工具调用/拒答边界/分类标准/结构化抽取规则;若问题是"知识不够新"或"依赖外部文档"则更适合 RAG)、标签质量(正确一致无歧义)、是否覆盖失败案例(badcase:答错/拒答错/格式错/工具调错/幻觉)、是否和现有能力有增量(prompt 能稳定解决则不微调)、是否能被评测验证(留验证集看准确率/格式遵循率/拒答准确率/工具调用成功率)。 - DeepSeek R1 训练方法(拔高知识点):训练过程六步:(1)向 DeepSeek-R1-Zero 提问再人工精修生成几千条思维链监督数据集;(2)用该数据集训练 DeepSeek v3 base 得到思维链 SFT 模型;(3)用 GRPO 强化学习,奖励引入准确率和语言一致性分数,得到 RL 模型;(4)用 RL 模型拒绝采样收集 60 万条思维链推理数据;(5)向 DeepSeek-v3 提问整理 20 万条写作/事实问答/自我认知非推理数据,整合 60 万推理数据得 80 万监督数据集;(6)用 80 万数据集训练 v3 base,再做多样化强化学习得 DeepSeek-R1。背后四思想:闭环迭代(训模型 -> 用更强模型生成更好数据 -> 再训 -> 共同进化)、数据质量优先(拒绝采样、人工精修、模型奖励打分)、分阶段训练(SFT 学指令 -> GRPO 优化推理 -> 多场景 RL 提泛化和安全)、多类型数据集互补。

量化方法:PTQ(训练后量化 Post-Training Quantization 训练完成后把浮点权重和激活转 INT8,优点实现简单成本低缺点没考虑量化误差精度下降明显);QAT(量化感知训练 Quantization-Aware Training 训练中模拟量化插入伪量化节点让模型"感知"误差,优点精度接近浮点缺点训练成本高需从头训练);QAF(量化感知微调 Quantization-Aware Fine-tuning 基于预训练模型微调阶段加量化感知,比 QAT 成本低精度略低于完整 QAT 但远好于 PTQ)。 - 量化好处:降低计算和存储成本(FP32->INT8 减内存和带宽提升速度降能耗,适合边缘移动端);支持大模型在有限硬件运行(QLoRA 4-bit 让 650 亿参数模型在单张 48GB GPU 微调);降低部署成本。 - 量化坏处:精度下降(低精度表示范围有限,权重激活细微差异被放大);累积误差(深层网络量化误差逐层累积,注意力机制和归一化算子表现明显)。 - 剪枝:去除不重要连接或神经元。非结构化剪枝(随机移除单个权重/连接,压缩比大但推理速度提升不大);结构化剪枝(按规则移除整个神经元/滤波器/层,更适合硬件加速)。 - 二值化:极端量化,把权重和激活限制在 +1/-1 两个值。 - 模型压缩技术选择:极端资源受限场景优先二值化和量化;注重计算效率且要精度则量化和结构化剪枝;保持性能前提下压缩则知识蒸馏。 - 推理框架对比(vLLM / Llama.cpp / FasterTransformer / DeepSpeed-Inference / ONNX Runtime):vLLM 高效兼容 HuggingFace;Llama.cpp 超轻量支持 4-bit/8-bit 量化;FasterTransformer 是 NVIDIA 出品;DeepSpeed-Inference 支持分布式推理;ONNX Runtime 通用支持 INT8 量化。 - 为什么 Llama.cpp 在 CPU 上效果更好(飞书作者用 Llama.cpp 替代 ONNX Runtime,CPU 推理速度提升 1 倍以上):(1)内核优化,llama.cpp 对 LLM 做高度融合算子(注意力、RoPE、KV cache),减少框架调度和内存拷贝,ONNX Runtime 是通用框架调度开销大;(2)线程与缓存策略,llama.cpp 主动优化线程亲和、NUMA 绑定、缓存布局,KV cache 访问高效;(3)指令集利用,llama.cpp 直接用 AVX2/AVX-512 等 SIMD 指令,对矩阵乘法和量化内核手工优化。一句话:llama.cpp 专门为 LLM 推理做极致优化,ORT 是通用框架调度和内存管理开销大。 - vLLM 框架介绍:设计思路是解决大模型推理高并发和显存瓶颈,传统框架 KV Cache 占显存大且碎片化,vLLM 用 PagedAttention 把 KV Cache 分页管理(类似 OS 虚拟内存分页),显存复用率高,适合长上下文和多请求,实现高效显存利用和动态批处理。特点:PagedAttention、动态批处理、高兼容性(支持 HuggingFace Transformers 模型几乎无需改代码)、分布式推理。 - 项目如何做推理加速(飞书作者核心面试题):优化邮件日历事件提取模型。背景是用户需从邮件快速创建日程,但云端 API 延迟 2-3 秒且按调用计费不适合高频。方案本地部署微调后的 Qwen2.5-7B-Instruct,三步优化:(1)LoRA 微调:用 PEFT 库实现低秩适应,只训练 0.18% 参数(1400 万 vs 76 亿),任务准确率从 65% 提升至 92%;选 LoRA 而非全量微调是因成本和效率;数据来源真实用户邮件标注 + GPT-4 合成 + Enron Email Dataset,500 条,Azure AI Foundry 训练。(2)DPO 对齐:用 TRL 库 Direct Preference Optimization 优化输出质量;构建 200 对 chosen-rejected 偏好数据,chosen 来自人工标注高质量输出,rejected 通过规则扰动(添加冗余字段、格式错误、信息缺失)生成并混合少量 GPT-4 负样本;在 LoRA 基础上训练 1 小时,JSON 格式规范性从 85% 提升至 98%。(3)量化部署:技术选型对比 ONNX Runtime、PyTorch Mobile、llama.cpp,选 llama.cpp 因 CPU 推理深度优化(SIMD 并行计算 + 内存管理优化),比 ONNX 快 2.5 倍;量化用 torch.ao.quantization 库,方案 Q4_K_M 混合精度 PTQ(Attention 层 5-bit、FFN 层 4-bit、输出层 6-bit);模型从 14GB 压缩到 4.3GB,推理速度从 154 秒降到 43.7 秒提升 3.5 倍,准确率只损失 2.5%(92%->89.5%)。项目价值:LoRA + PTQ 组合,不牺牲太多精度下把云端依赖转本地部署,成本从按次计费降为零边际成本,满足实时响应。

RL 理论链条完整。飞书跳过了 MDP/贝尔曼/MC/TD/策略梯度/REINFORCE/Actor-Critic,本课表要求按这条链学完,因为不学 Actor-Critic 就讲不清 PPO 的 Critic 价值头从哪来,讲不清 GRPO 为什么能省掉 Critic。 3. DPO/GRPO 要能对比取舍。飞书只列了 RLHF/RLAIF/DPO 三方案,本课表补上 GRPO,并能讲清"DPO 省掉奖励模型和 PPO、训练简单但只能用偏好对数据;GRPO 省掉价值网络、适合可验证奖励(准确率)的推理任务;PPO 最通用但工程最复杂、最不稳定"的工程取舍。 4. 量化要懂三类方法与混合精度。飞书讲了 PTQ/QAT/QAF 和 Q4_K_M 混合精度,本课表要求能解释为什么 Attention 层留 5-bit、FFN 压到 4-bit、输出层用 6-bit(注意力对数值敏感不能压太狠,FFN 参数最多压缩收益最大,输出层影响最终 logits 分布需保护)。 5. 跑通要留下可复现的评估闭环。飞书强调"评估集先行"和"不能使用未运行的目标值代替实验结果",本课表要求学生像飞书后训练项目那样:先冻结 51 条评估集 -> 训练前后用同一冻结集对比 -> 记录 Base->SFT->DPO->量化的真实数值,不能编造。 6. 架构演进要联系到推理。尚硅谷讲 MLA/GQA/MoE,本课表要求能讲清"GQA/MQA/MLA 怎么减少 KV Cache 显存"(直接关系 vLLM 的 PagedAttention 显存压力),"MoE 稀疏激活怎么降推理计算量"。

面试要点(具体八股题及答法)

  1. LoRA 原理与显存计算:LoRA 假设权重更新 ΔW 是低秩的,用 ΔW=A·B 分解(A 是 d×r,B 是 r×d,r 远小于 d,如 r=8 而 d=4096),冻结原权重 W,只训练 A、B,参数量从 d² 降到 2dr。推理时 W' = W + (α/r)·A·B。显存计算(必背具体数字):全参微调(bf16 权重 14GB + 梯度 14GB + Adam 状态 fp32 的 momentum+variance 两份 56GB = 约 84GB,单卡 80GB 都勉强,必须分布式 + ZeRO);LoRA 微调(冻结 base 权重 14GB + LoRA 参数极少 0.18% 即 1400 万,主要开销激活值约 16~20GB,单卡 24GB 可跑);QLoRA 微调(4-bit NF4 base 3.5GB + LoRA 适配器 fp16 + 优化器状态约 6~8GB,单卡 16GB 可微调 7B)。
  2. QLoRA 与 LoRA 区别:LoRA base model 保持 fp16/bf16 只训低秩适配器;QLoRA base model 量化到 4-bit NF4(NormalFloat4 针对正态分布权重优化的量化格式),引入双量化(Double Quantization 对量化常数再量化省内存)、分页优化器(Paged Optimizer 用 CPU offload 防峰值显存溢出),LoRA 适配器保持 fp16。7B 单卡 16GB 可微调,65B 单卡 48GB 可微调。
  3. SFT 数据格式:alpaca({"instruction": "...", "input": "...", "output": "..."} 单轮);shareGPT({"conversations": [{"from":"human","value":"..."},{"from":"gpt","value":"..."}]} 多轮)。训练时用 Response-only Loss(只对 assistant 输出部分算 loss),并用模型原生 ChatTemplate,训练和推理必须一致。
  4. RLHF vs DPO vs GRPO 区别(高频题):RLHF 三阶段 SFT->奖励模型(人类排序数据训练)->PPO(+KL Penalty 防漂移),需要训练奖励模型和价值模型,工程最复杂最不稳定但最通用,代表 ChatGPT、Claude;DPO 直接用偏好对 chosen/rejected 优化策略绕过奖励模型和 PPO,损失基于 Bradley-Terry 模型推导,训练简单稳定只需偏好对数据但只能用偏好数据不能利用可验证奖励,代表 LLaMA-2-Chat、Mistral-Instruct,飞书项目用 DPO 150 对数据训 1 小时 JSON 规范性 85%->98%;GRPO DeepSeek 提出对同一 prompt 采样一组 group 回答用组内相对优势替代 Critic 价值网络省去价值模型降显存,适合有可验证奖励(准确率、语言一致性)的推理任务,DeepSeek-R1 用 GRPO。选型口诀:有可验证奖励的推理任务选 GRPO;只有偏好对数据想快速对齐选 DPO;需要最通用对齐有资源调稳定选 PPO/RLHF。
  5. SFT 和 RLHF 区别:目标(SFT 给基本语言和任务能力;RLHF 对齐人类偏好安全价值观);方法(SFT 有监督数据问题-答案;RLHF 强化学习数据含多答案 + 排序 + 奖惩模型);步骤(RLHF 在 SFT 基础上进一步优化,先 SFT 再 RL)。
  6. vLLM / KV Cache / PagedAttention / Continuous Batching:KV Cache Transformer 自回归生成时每生成一个 token 需要前面所有 token 的 Key/Value,缓存它们避免重算,长文本加速显著,缺点显存占用大易碎片化;PagedAttention vLLM 核心把 KV Cache 按页 block 管理类似 OS 虚拟内存分页避免碎片化;Continuous Batching 动态批处理异步调度器把不同请求动态合并;vLLM 适用场景 在线高并发推理长上下文和显存受限场景,核心创新是 PagedAttention + Continuous Batching。
  7. 量化 INT8 / INT4 及混合精度:INT8 FP32->INT8 速度提升 2~4 倍内存降 4 倍,方法 PTQ/QAT/QAF;INT4 更激进内存降 8 倍,QLoRA 用 NF4;混合精度 Q4_K_M(飞书项目实例)Attention 层 5-bit(注意力对数值敏感不能压太狠)、FFN 层 4-bit(参数最多压缩收益最大)、输出层 6-bit(影响最终 logits 分布需保护),结果 Qwen2.5-7B 从 14GB 压到 4.3GB,推理 154 秒->43.7 秒提升 3.5 倍,准确率 92%->89.5% 仅损失 2.5%。
  8. 蒸馏 vs 剪枝 vs 量化 vs 二值化:蒸馏(大教师训小学生,软标签学习,保持性能降成本,适合"保持性能前提下压缩");剪枝(删不重要连接/神经元,非结构化压缩比大但提速不大,结构化适合硬件加速,适合"注重计算效率且要精度");量化(FP32->INT8/INT4 可调压缩精度,适合"资源受限且需平衡");二值化(极端量化 +1/-1,适合"极端资源受限且精度要求不高")。
  9. 你是怎么做微调的 / 数据集怎么做的(必考,飞书四步法 + 六标准):四步法:确定目标/选型(先判能否用 prompt/RAG,16GB 用 LoRA、13B 用 QLoRA)-> 数据集准备(内部 + 公开 + 人工 + 合成,文本标准化/敏感信息去除/平衡/标签纠正/统一格式)-> 确定参数微调部署(r/alpha/lr/epochs,监测损失曲线防过拟合,早停 + 正则化,PEFT 合并权重)-> 验证评估(分类 F1、生成 BLEU/ROUGE、对话 MT-Bench、结构化提取字段级 F1 + 精确匹配)。判断数据是否值得训练六标准(腾讯真题):真实覆盖业务问题、有明确可学习模式、标签质量高、覆盖失败案例、和现有能力有增量、能被评测验证。
  10. 你的项目如何做推理加速(飞书核心题,背完整三步):背景(云端 API 延迟 2-3 秒且按次计费不适合高频)-> LoRA 微调(PEFT 库,0.18% 参数,65%->92%,500 条数据 Azure AI Foundry)-> DPO 对齐(TRL 库,200 对 chosen-rejected,rejected 规则扰动生成,JSON 规范性 85%->98%)-> 量化部署(llama.cpp 比 ONNX 快 2.5 倍,Q4_K_M 混合精度 PTQ,14GB->4.3GB,154 秒->43.7 秒提升 3.5 倍,准确率仅损失 2.5%)。

阶段 8:多模态(2 周)

尚硅谷细节(从零实现,重代码落地)

  • 多模态概论:理解文本、图像、音频等多模态统一到向量空间的思路。
  • ViT(Vision Transformer,视觉 Transformer):把图片切成 patch(图像小块),每个 patch 线性投影成一个 token,加位置编码,送入标准 Transformer Encoder 做图片分类。核心是把"图像"变成"序列",复用 NLP 的 Transformer 架构。从零实现图片分类任务。
  • CLIP(Contrastive Language-Image Pre-training,对比式图文预训练):OpenAI 提出,用对比学习让"图像"和"文本"对齐到同一向量空间。训练目标是让正确图文对的相似度最高、错误对最低。落地能力是"文搜图"(输入一句话检索最匹配的图片)和"图搜文"。从零实现文搜图。
  • ClipCap:在 CLIP 图像特征之上接一个 mapping network(映射网络,通常是 Transformer),把图像特征"翻译"成前缀 token,再喂给 GPT 做 caption,实现"图生文"。
  • Diffusion Model(扩散模型):核心思想是"前向加噪"(逐步往图片加高斯噪声直到变成纯噪声)+"反向去噪"(训练一个神经网络逐步预测并去除噪声,从纯噪声还原出图片)。从零实现。
  • Conditional Diffusion(条件扩散):在去噪过程中额外注入条件信息(如文本 prompt、类别标签),让生成的图受条件控制。从零实现。
  • Dall-E2(文生图):OpenAI 的文生图模型,先用 CLIP 文本编码器把 prompt 编成文本特征,再用 prior(先验模型)把文本特征映射到图像特征空间,最后用条件扩散解码器生成图片。从零实现文生图。

项目八·智能检索(重点项目,2 周内优先完成):基于 CLIP Chinese(中文版 CLIP)模型进行续训(继续训练而非从头训);采用部分参数冻结策略:重点解冻文本端后 3 层与视觉端后 2 层,其余层冻结,只训练这几层 + 投影层--为中文垂直领域适配,同时省显存防过拟合;优化器 AdamW 分组学习率与权重衰减(不同层组用不同学习率,衰减系数也分组);训练策略组合 线性预热 warmup + 余弦衰减 cosine decay + 梯度裁剪 gradient clipping + 早停 early stopping;推理与检索用优化后的模型把图像编码成归一化特征向量(L2 归一化,使点积=余弦相似度),存入基于 HNSW 索引(Hierarchical Navigable Small World 层级可导航小世界图,近似最近邻索引)的 Chroma 向量数据库;相似度计算用点积相似度(向量已归一化,点积等价余弦);硬件成本单张 V100 GPU,显存占用约 15GB,训练时长约 5 小时(可直接写进简历的硬指标)。

项目九·智能发布(图生文标题生成):训练时完全冻结图像编码器(只复用 CLIP 视觉端不更新);通过 CLIP 视觉模型提取图像特征并提前存储(预计算,避免每轮重复编码);将图像特征通过投影层映射成一段提示词序列(prompt prefix);替换文本嵌入中对应的占位符向量(placeholder token);用自回归采样(autoregressive sampling,逐 token 生成)生成推荐标题。

阶段 9:前沿热点(2 周)

尚硅谷细节

  • Harness Engineering(马具工程):课程明确说"based on Hermes Agent"。Harness 直译"马具/挽具",类比给马套上缰绳辔头--大模型就是那匹烈马,Harness 就是套在外面让它可控、可调、可用的"控制层"。核心公式:Agent − Model = Harness(一个 Agent 减去底层大模型,剩下的全是 Harness:提示词、上下文管理、工具、记忆、循环、权限、编排)。2026 年最热的前沿方向。
  • Vibe Coding(氛围编码):意图驱动型编程范式--人类不再逐行写代码,而是定义"需求意图",AI 落地代码实现。开发者关注"vibe"(整体感觉和方向)而不是语法细节。Cursor、Claude Code、Windsurf 都是 Vibe Coding 工具。
  • OpenClaw(小龙虾):开源智能体平台,定位常驻型 AI 助手(不是一次性问答,而是长期挂在线上陪你干活)。特点:多渠道消息接入(微信/飞书/钉钉/邮件/Slack)、工具调用、技能扩展、日常任务处理。
  • Hermes Agent(爱马仕):self-improving(自我改进)的 AI Agent。核心机制是 built-in learning loop(内置学习循环):从经验中创建并改进 skills、搜索过往对话、跨会话建立用户模型。架构上是 Agent Runtime(运行时)+ Agent Host(宿主)+ 控制外壳,把原始大模型转化为可控自治体的基础设施层。支持定时任务与多平台接入。

飞书对应细节(从 AI_通用素养.md 读到的具体内容,文档分四大块:提示词工程 / Harness Engineering / SKILL / Claude Code)

  1. 提示词工程(具体技巧):不是死记模板,而是理解"提示词是控制大模型行为的接口"。核心技巧:角色设定、任务分解、Few-shot(给少量示例)、Chain-of-Thought(让模型一步步推理)、输出格式约束(JSON Schema)、负面指令(不要做什么)。这是 Harness 的最朴素形态--纯靠 prompt 控制模型。
  2. Harness Engineering(飞书这一块最厚,是阶段 9 的核心深化): - Agent − Model = Harness:模型本身能力固定,Agent 的差异全在 Harness。 - 演进脉络:Prompt Engineering(2023-2024) -> Context Engineering(2025) -> Harness Engineering(2026)。从"调提示词"到"管理上下文"再到"工程化整个控制层"。 - 三层记忆模型(必背):① Active Context Window(活动上下文窗口,即模型当前能看到的 token,容量有限)② Working State(工作状态,当前任务的中间产物,如已读文件、已写代码)③ Durable Memory(持久记忆,跨会话长期存储)。对应工具就是 /compact(把长上下文压缩成摘要腾出窗口)和 /rewind(回退到之前的状态)。 - AGENTS.md:一个让 Agent 把长期记忆和约定沉淀成文件的标准(对应论文 arxiv 2602.11988),类似 CLAUDE.md 但是面向多 Agent 协作。 - Loops(循环模式)四种:① Ralph Wiggum(简单重复循环,失败就重试)② Plan-then-Execute(先规划再执行)③ Hypothesis-Verification(假设-验证循环)④ TDD(测试驱动开发循环,先写测试再让 Agent 实现)。 - Tool Hygiene(工具卫生):工具返回结果要做处理--截断(太长截断防撑爆上下文)、抽帧(视频/长文档抽关键帧)、落盘(大结果写磁盘只把引用给模型)。 - Structural Constraints(结构约束):用 JSON Schema、类型系统、强制流程约束 Agent 输出,不靠"请你输出 JSON"这种软约束。 - 三档权限 Guardrails(护栏):Agent 调工具分权限等级--只读 / 可写但受限 / 危险操作需人工确认。 - Orchestration(编排):Single Agent vs Multi-Agent 的取舍。Multi-Agent 有协调税(coordination tax,多个 Agent 通信协作的额外开销);模式有 Orchestrator-Worker(一个主控派活给多个工人)、Reflection(一个 Agent 做完另一个 Agent 反思审查)。 - Anthropic Harness(Anthropic 自己的 Harness 范式,必背五要素):① Initializer(初始化,建工作区、读约定)② Coding Loop(编码主循环)③ External Memory(外部记忆,不靠模型自己记,落盘)④ Deterministic Validation(确定性验证,用测试/规则验证而非让模型自己说对不对)⑤ Sandbox(沙箱,在隔离环境执行防破坏)。关键原则:每个 Agent 只活一次(stateless,不依赖 Agent 内部状态跨任务累积,每次重新初始化)。 - ClawCode:一个 Harness 实现案例,5 阶段流水线,涉及 OmX/clawhip/OmO 等内部组件(笔记里把 CC、OpenClaw、Hermes 三个开源架构并列为都用 orchestrator 模式)。
  3. SKILL(Anthropic 的 Skill 体系): - 什么是 SKILL:一个 Skill = SKILL.md(主说明文件)+ Scripts(可执行脚本)+ References(参考文档)+ Assets(资源文件如模板)。它不是死提示词,而是一个"可加载的工具包"。 - 渐进式披露(Progressive Disclosure):SKILL.md 只放最关键的入口信息,详细内容按需从 References 加载,避免一开始就把上下文撑爆。这是 SKILL 区别于普通 prompt 的核心设计。 - 规范:单个 SKILL.md 建议 ≤500 行。 - 7 条最佳实践(写好 Skill 的准则)。 - code-review plugin(代码审查插件):一个具体 Skill 案例,分 7 阶段执行代码审查。 - 置信度 rubric(评分量表):用 LLM-as-Judge 给审查结果打置信度分,分档 0 / 25 / 50 / 75 / 100,并设 80 阈值(≥80 才算高置信采纳)。这套分档在滴滴社招面经里被反复考。 - SKILL vs MCP:MCP(Model Context Protocol)是让 Agent 连接外部工具/数据源的标准协议(管"怎么接工具");SKILL 是封装 Agent 能力的知识包(管"怎么做某类任务")。两者正交,可组合。 - SKILL vs Prompts:Prompt 是一次性文本指令;SKILL 是结构化、可复用、渐进披露、带脚本和资源的封装。
  4. Claude Code(从入门到精通): - 是什么:Anthropic 官方的通用编程 Agent(终端里跑,能读写文件、执行命令、改代码、跑测试)。 - 核心命令:/init(初始化项目,自动生成配置)、/memory(管理记忆)、CLAUDE.md(项目级约定文件,告诉 Claude Code 这个项目的规范、依赖、禁忌)。 - 接入与定价:Pro 版 $17/月、Max 版 $100/月。 - 实战案例:YouTube 案例(用 Claude Code 完成一个真实项目的工作流演示)。 - 工作流要点:先 /init 建 CLAUDE.md 约定 -> 让它读代码 -> 给明确任务 -> 它自主编码循环 -> 用测试做确定性验证(对应 Anthropic Harness 的 Deterministic Validation)。

论文对应(论文.md):AGENTS.md 论文(arxiv 2602.11988)提出把 Agent 的长期记忆、约定、经验沉淀成 AGENTS.md 文件,让多 Agent 共享上下文,直接对应 Harness 的 Durable Memory;Attention Residuals(Kimi)注意力残差连接,附 5 道面试问答,作为底层模型结构前沿储备。

  • 不要追求每个项目都做:阶段 6 选 1 个 RAG/Agent(飞书 RAG-Agent 项目),阶段 7 选 1 个微调(智能评论)+ 1 个差异化(Rasa 或 NL2SQL),阶段 8 选 1 个多模态(智能检索)。简历 2-3 个项目足够。
  • 面试不必等学完:第 16 周就开始投,面试中发现的问题反哺学习(飞书作者就是这样迭代笔记的)。
  • 算法深度按目标调:若中途确定只走应用岗,阶段 7 可降到"理解能答"(回到飞书"跑通即可");若冲算法岗,阶段 7 要加论文阅读(飞书「论文」章节)。
