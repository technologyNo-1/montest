### 3.2 你的两个核心项目（简历中的核武器）

#### 项目一：NL2SQL 企业级自然语言查询系统

**简历写法（根据 STAR 法则优化后）：**

> **NL2SQL 企业级自然语言转 SQL 系统** | Python, FastAPI, LLM, SQL, Embedding
>
> - **背景：** 企业内部非技术人员无法直接查询数据库，数据分析师每天花费 30% 时间编写简单查询 SQL
> - **方案：** 从0到1设计并实现了基于 LLM 的 NL2SQL 系统，采用 7 阶段请求处理管道（Schema提取→Prompt构建→FewShot检索→SQL生成→6层安全校验→执行→结果处理）
> - **核心技术：**
>   - 用 Embedding 向量检索实现 20+ 表的自动选表（Top-K 精度 95%+）
>   - 设计了 6 层纵深防御安全模型：关键字白名单 → 黑名单 → AST语法解析 → 表/列名白名单 → LIMIT注入，确保 SQL 注入零风险
>   - 实现了 Few-Shot 示例的 Embedding 匹配 + 自动入库机制（用户修正的 SQL 自动成为新示例）
>   - 支持 SQLite/PostgreSQL/MySQL 多数据库，通过环境变量零代码切换
> - **成果：** 非技术人员数据查询效率提升 10 倍，数据分析师简单查询工作量降低 60%

**面试中可以展开的亮点：**
- 为什么用 LLM 而不是微调模型？（表结构频繁变更，LLM 零成本适配）
- 安全模型的6层设计思路（纵深防御，每层解决什么问题）
- 如何处理大 Schema（20+表，100+列）的 Token 限制？（Embedding 检索只送相关表）
- Prompt Caching 如何降低延迟和成本？

#### 项目二：Spark 百GB级用户画像处理优化

> **每日 100GB 用户画像日志 Spark 处理优化** | Spark, Hive, Parquet, HDFS
>
> - **背景：** 每日 100GB+ 用户行为日志（3-5亿条记录），早上 8:00 前必须产出 5000万用户画像标签宽表，供推荐/广告/推送系统使用
> - **技术挑战与解决方案：**
>   - **数据倾斜：** 头部 1% 用户贡献 40% 日志量 → 采用 Salting（随机前缀打散）+ 两阶段聚合，倾斜 SubTask 负载从 100% 降到 30%
>   - **小文件问题：** 上游每小时分区存在大量小 Parquet → 配置 `spark.sql.files.maxPartitionBytes` + 定期 Compaction
>   - **Shuffle 优化：** 用户维度聚合时 Shuffle 数据量爆炸 → Broadcast Join 小表 + 调整 `spark.sql.shuffle.partitions`
>   - **增量与全量合并：** 每日增量标签与历史全量合并 → 实现拉链表机制，保证数据一致性
> - **成果：** 处理时间从 90 分钟优化到 25 分钟（3.6x 提升），资源利用率提升 60%，SLA 达成率 99.9%

## 四、项目包装：把你已有的东西变成面试核武器

### 4.1 NL2SQL 项目深度包装（你的最强武器）

这个项目是你区别于其他 5 年大数据开发的最大差异化优势。**面试官很可能没怎么见过这种项目，所以你有主动权来定义它的价值。**

**准备以下 10 个问题的回答（面试官大概率会问）：**

1. **"这个项目的背景是什么？解决了什么问题？"**
   → 准备一个 1 分钟的电梯演讲版本

2. **"为什么用 LLM 而不是直接写规则？"**
   → 对比：规则方案维护成本高、无法泛化；LLM 方案零样本学习、Schema 变更零成本

3. **"架构上最大的挑战是什么？你怎么解决的？"**
   → 大 Schema 的 Token 限制 → Embedding 检索方案
   → SQL 安全性 → 6层纵深防御
   → 生成质量 → Few-Shot + Prompt Engineering

4. **"安全模型具体怎么设计的？每层分别解决什么问题？"**
   → 准备一张架构图（可以在面试时画出来）

5. **"如果表有 100 张，每张 50 列，Token 不够怎么办？"**
   → Embedding 检索 Top-K 表 + 列裁剪 + 采样数据而非全量

6. **"怎么评估生成的 SQL 质量？"**
   → 人工评估准确率 + 用户修正率 + 置信度阈值

7. **"这个方案在生产环境的局限性是什么？"**
   → LLM 延迟（2-5s）、复杂 Join 可能选错表、成本控制

8. **"如果让你重新设计，你会做什么不同？"**
   → 展示技术前瞻性：如增加 Query 改写、多轮对话、Agent 架构

9. **"你怎么看待 NL2SQL 这个方向的前景？"**
   → 结合 AI Native 趋势：数据民主化、Text-to-Everything

10. **"你在这个项目中最大的收获是什么？"**
    → 不仅技术，还有"如何让 AI 可靠地嵌入生产系统"的系统思维

### 4.2 Spark 优化项目包装

**核心叙事角度：不是"我调了几个参数"，而是"我理解 Spark 底层原理，所以知道在哪下手"。**

准备回答的追问：
