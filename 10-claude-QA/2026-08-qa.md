## 08-08 · 企业 Agent 工程方法论(5 问)

> 这 5 问围绕一个核心张力:**规则的刚性 vs LLM 的自主性 vs 验证的必要性**。

### Q1:企业 agent 危险操作如何限制?skill 要设计很复杂吗?作者写了规则我都能违反,怎么限制?

**A:危险操作的限制不在 skill 层,在框架层。**

- **软规则 vs 硬约束**:skill 是软规则(可违反,如 reflow 没造成损害);权限是硬约束(不可绕过,如删库/发生产)
- **靠四件事**:权限系统(allow/deny)、沙箱隔离、人在回路(高风险确认)、审计日志
- **划分自主边界**:风格/选型 LLM 自主;破坏性操作(写生产/删数据/对外发布/花钱/改权限)必须确认
- **skill 不需很复杂**,复杂的是权限和验证框架 -- 把精力放框架层硬约束,而不是 skill 里穷举"不许做X"

### Q2:agent 不需人介入?如何自动验证 + 把控不偏离 + 理解业务 + 验收差值,且不需人介入?

**A:完全不需人介入是理想,现实是"减少介入频次、提高介入质量"。**

- **自动验证四法**:① 结构化验收标准(开始就定客观标准);② agent 自检循环(grep/测试);③ LLM-as-judge rubric 打分;④ 差值检测(验收清单逐项核对)
- **纯自动有上限**:业务背景/审美/隐性需求 LLM 判断不了(这次"太精炼"就是我没判断出你要细节)
- **最佳 = 分段介入 + 自动验证**:关键节点(需求/方向/验收)人介入,执行自动化;自检消化低级错误,人只在判断密度高的地方介入
- **人介入不是受限于人**,是把人用在刀刃上(判断),执行交给 agent
- **完全自动化**只适合标准化 + 有客观验收标准的任务(迁移、测试生成);需求模糊/审美的任务人介入不可避免

### Q3:每次细微需求都写记忆,不是要记超级多?最佳实践?

**A:记原则不记细节,记可复用判断/教训,不记一次性产出。**

- **判断标准**:下次还会用到吗?通用原则还是一次性细节?
  - 记"HTML 要自检 class"(原则)✓
  - 不记"课表用了可滚动"(一次性细节)✗
- **企业分层**:组织级(共享 skill/规范)/ 项目级 / 个人级,避免重复
- 去重合并,定期清理

### Q4:skill 和传统业务代码差距很大?传统难处理?要预先想到或做限制?匹配很多测试?我的认知对吗?

**A:认知基本对,补两点。**

| | 传统业务代码 | skill/agent |
|---|---|---|
| 逻辑 | 确定性,穷举分支 | 判断性,原则+运行时判断 |
| 质量保证 | 测试覆盖所有 case | 原则+自检+人在回路 |
| 没覆盖的情况 | 崩溃或错误(不可控) | LLM 尝试判断(可能对可能错) |
| 模糊需求 | 难处理(写死或报错) | 能权衡 |

- 传统"这种情况"(6 万字细节要完整)确实难处理,这是 agent 的真实优势
- **但 agent 不万能**:确定性/高可靠/强一致场景(金融/计费/权限)传统代码更合适
- **最佳 = 确定性用代码,判断性用 agent,结合**(如 RAG:检索用代码,生成用 LLM,安全过滤用代码)
- 纠正:传统也用异常处理/灰度/监控兜底,不是纯靠预判;agent 也需要这些(自检代替部分测试,rubric 代替部分断言)

### Q5:skill 让代码有员工感觉,迭代比传统快 100 倍?如何利用崛起?

**A:方向对,但"100 倍"分场景。**

- **提速看任务**:
  - 创造性/模糊/迭代(生成/原型/探索/内容):10-100 倍 ✓
  - 复杂架构/设计:2-3 倍
  - 高可靠核心系统(交易/实时/合规):不快甚至更慢 ✗
- **"员工感觉"对**:agent 像初级员工,能自主完成有边界任务,需方向/验收/纠偏
- **范式级优势(4 转变)**:从指令→意图;从穷举→原则+判断;从开发完才验证→边生成边自检;从产品→能造产品的员工
- **适合**:内容生成/原型/数据分析/文档/测试/重构/探索/个性化
- **不适合**:核心交易/实时控制/强合规/性能极限
- **崛起杠杆 = 把你的判断沉淀成 skill/记忆让 agent 复用**,判断越可复用、越结构化,杠杆越大
- **两个风险**:① 产出参差,验收能力必须跟上;② 过度依赖会丧失自己判断力

## 08-08 · 知识 / Context 治理与自我进化

### Q1:zara 说"不用整理,丢给 AI 自己长知识库"对吗?

**A:对一半,补一半。**

- **对**:AI 能看乱数据,不用像给人看那样预先精细结构化,降低预整理门槛
- **补**:"根本不用整理"过度了 -- 检索效率和 context 成本受影响,完全不整理慢且费 token;"自己长知识库"不对,AI 是被调用时提取+沉淀,需触发和沉淀机制
- **正确表述**:不用给人看的方式整理,但用 AI 友好的方式组织(可检索 + 轻量索引)

### Q2:所有内容给 AI context 会撑爆吗?都写记忆?还是做本地文档?

**A:分层,不混在一起。**

| 层 | 作用 | 容量 | 放什么 |
|---|---|---|---|
| Context(工作记忆) | 当前任务活跃信息 | 小(1M 也会压缩) | 当前任务需要的子集 |
| 记忆(持久事实) | 跨会话判断/约束 | 小,结构化 | 可复用原则、偏好、约束 |
| 文档(外部存储) | 原始素材和产出 | 大,无限 | 原始材料、详细内容、历史产出 |

- 都给 context **会撑爆** → 原始存文档,按需读子集(这次飞书 1.7MB 我切 18 章按需读)
- **不能都写记忆**(只记判断/约束,不记内容)
- 原始材料做本地文档,AI 工具按需读

### Q3:怎么治理?

**A:4 层架构。**

1. **原始层**:原始材料存文件,松散组织即可(信 zara,不用精细结构)
2. **索引层**:轻量索引 -- 每个文件/目录一句话摘要(AI 可自动生成),帮快速定位
3. **记忆层**:跨会话判断/约束/偏好,结构化,定期去重清理
4. **Context 层**:任务开始时根据索引判断读哪些文件,按需加载子集

> 治理动作就三件:原始不整理 + 加轻量索引;记忆定期去重/清理;context 按需加载。

### Q4:如何自我进化不介入循环?

**A:5 机制闭环 + 人审兜底。**

1. **触发式提取**:任务时从原始材料提取(原始不动,提取结果用完即弃)
2. **经验沉淀**:任务后自动判断"有什么可复用经验",写记忆(标准:原则不细节)
3. **记忆维护**:AI 定期自检记忆,去重/合并/清理过时
4. **索引自动更新**:新材料加入时自动生成摘要
5. **自检闭环**:每个任务后自检(做了什么/质量/教训),沉淀

> **完全不需人介入有边界**:AI 判断"记什么"可能偏差,需定期人审纠偏;业务判断/审美仍需人介入。

### Q5:最佳实践?

**A:**

- 原始材料不整理,存文件(信 zara)+ 加轻量索引(AI 友好组织)
- 记忆只记可复用判断/约束,定期清理(防爆炸)
- Context 按需加载,不全塞
- 自我进化闭环:提取 → 沉淀 → 治理,但定期人审纠偏
- 人在回路卡在判断密度高的节点(需求/方向/验收/记忆审计)

> **zara 话修正版**:不用给人看的方式整理知识库,但用 AI 友好的方式组织;AI 不会自己长知识库,要设计"任务触发提取 + 经验沉淀记忆 + 定期治理"闭环;完全自治是理想,定期人审纠偏是现实。
