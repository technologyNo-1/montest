### 2.2 按角色的优先级建议

**投资者视角**：
| 优先级 | 行动 | 原因 |
|:---:|------|------|
| 1 | 跟踪 NVIDIA 毛利率变化 | 毛利率 <70% = GPU 护城河裂开的第一个信号 |
| 2 | 跟踪 Anthropic ARR vs Claude Code ARR | Claude Code 如果 ARR 占比膨胀 → 从模型公司变成应用公司 |
| 3 | 等待 OpenRouter 估值变化 | Token 金融化的第一枚棋子 |

**产品/创业者视角**：
| 优先级 | 行动 | 原因 |
|:---:|------|------|
| 1 | 为"按结果计费"做准备 | Token 计费可能是短期过渡模式——设计"任务完成"指标体系 |
| 2 | 深度整合 MCP 生态 | 17,400+ 服务器，78% 企业团队已在生产中使用 |
| 3 | 关注模型无关架构 | 供应商锁定已被市场拒绝（79% 企业使用 3+ 模型）|

**企业采购视角**：
| 优先级 | 行动 | 原因 |
|:---:|------|------|
| 1 | 签署承诺消费折扣 | API 价格可能在 12-24 月内上涨 30-50%（补贴退场） |
| 2 | 多元化模型供应商 | 不要被 Anthropic 或 OpenAI 单一锁定 |
| 3 | 跟踪"合规税" | GDPR + AI Act 合规成本可能超过 API 费用本身 |

## 三、可重复的方法论 —— Token 产业调研框架

### 3.1 调研六层框架

```
第一层：物理层
  → GPU 出货量/存量/利用率/能效比
  → 模型参数量/架构/量化等级
  → 关键数据源: NVIDIA/AMD 财报, MLCommons, Fixstars, SemiAnalysis

第二层：定价层
  → API 定价(输入/输出)、GPU 租赁价、推理云价
  → 关键数据源: 各供应商官网、RunPod/Lambda/CoreWeave 官网

第三层：消费层
  → Token 量/行业拆分/地理拆分/人均
  → 关键数据源: a16z/OpenRouter、Vercel AI Gateway Index、Menlo Ventures

第四层：利润层
  → 毛利率/ARR/ARR 拆分/集中度 HHI
  → 关键数据源: 各公司财报（Anthropic 不上市→估算+交叉验证）

第五层：地缘层
  → 出口管制/碳关税/外资限制/补贴
  → 关键数据源: 政府公告、Bloomberg、Reuters

第六层：趋势层
  → 替代威胁(ASIC/开源/结果计费)/新玩家/颠覆情景
  → 关键数据源: 学术论文(arXiv)、分析师报告(Goldman/JPM/Bain)、VC 博客(a16z/Sequoia)
```

### 3.2 每次更新应检查的信号

```
频率：每月
  ├── 主要供应商 API 定价页（是否有降价/涨价）
  ├── OpenRouter 统计（Token 量 top 10 模型变化）
  └── Vercel AI Gateway Production Index（市场份额变化）

频率：每季
  ├── NVIDIA/AMD 财报（GPU 出货量/毛利率/中国收入）
  ├── Anthropic/OpenAI/Google ARR 指引
  └── Menlo Ventures LLM 企业报告

频率：每半年
  ├── a16z/OpenRouter State of AI 报告
  ├── 主要供应商战略变化（模型发布/定价模式/生态扩展）
  └── 出口管制政策更新
```

### 3.3 已知盲区与方法论建议

| 盲区 | 影响 | 缓解方案 |
|------|:---:|------|
| 企业内部自建 Token（不经过 API）| 全球 Token 总量可能被低估 30-50% | 从 GPU 出货量反推总产出 |
| 非公开公司的财务数据 | Anthropic/OpenAI 的利润率无法独立验证 | 多源交叉验证 + 公开声明追踪 |
| 中国国内市场数据 | 独立生态，OpenRouter 无法覆盖 | 从中国政策文件 + 公开公司有限数据推断 |
| 军用 Token | 完全黑箱，数据不公开 | 不纳入市场分析（但需注意其 DRC 影响） |
